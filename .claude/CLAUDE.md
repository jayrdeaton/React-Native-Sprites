# @tastic/sprites

Shared visual effects for React Native games - an SVG+Reanimated `Fireworks` celebration burst (ported from Hangman), a Skia+Reanimated `GravityWell` particle-swirl marker (ported from BoxHockey/Swirlio's near-duplicate implementations), a Skia+Reanimated `Portal` (vortex, rift or warp gate; built for DuelTastic's linked gates), a Skia+Reanimated `shapes` subpath (`ObstacleRect`, `GoalPost`, `Disc`, `CelebrationRings`, `MysteryPickup` - reconciled from BoxHockey/AirHockey/Pong/LightCycles/Snake's near-duplicate board dressing), and a Skia+Reanimated `hockey` subpath (`ZoneLine`, `FaceoffCircle`, `GoalDoorFlash`, `ScoreWedges` - reconciled from BoxHockey/AirHockey's near-duplicate two-goal rink chrome). Part of the `@tastic` package ecosystem.

Five subpath exports (`./fireworks`, `./gravity`, `./portal`, `./shapes`, `./hockey`), deliberately no root `"."` export - `Fireworks` and the other three have mutually exclusive optional native-rendering peers (`react-native-svg` vs `@shopify/react-native-skia`), and a shared barrel would force Metro to resolve both for any consumer. `gravity`, `portal`, `shapes`, and `hockey` are all Skia-only (no peer-isolation reason to split them from each other), kept as separate subpaths anyway since they're independently reusable concepts - a consumer wanting only `ObstacleRect` shouldn't need to know `GravityWell` exists. `hockey` specifically holds genre-specific rink chrome (BoxHockey/AirHockey only) rather than the more generic board dressing `shapes` holds - kept out of `shapes` so a non-hockey consumer of that subpath never sees hockey-only concepts like a faceoff circle or a goal door.

`shapes`' and `hockey`'s exports are deliberately thin, presentation-only wrappers - props in, pixels out, only ever local/cosmetic animation state (a ring's opacity, a flash's timing). None of them know what a "player," "score," or "goal" means as a game concept; a caller resolves per-player color before handing it in as a plain `color` prop. `Disc`'s `opacity`/`ringOpacity`, `CelebrationRings`' internal shared values, and `GoalDoorFlash`'s internal shared values all follow GravityWell's own "SharedValue in, SharedValue out" discipline - see each component's own doc comment. `hockey`'s own interactive/game-rules exclusions (BoxHockey's faceoff countdown pulse, its live-target tint, its ready-check breathing ring) are documented on `FaceoffCircle`'s own doc comment - real game state that stays app-local, layered by the caller around the static shape this package renders.

**`portal` (2026-11-08).** `Portal` takes GravityWell's "SharedValue in" props (`x`, `y`, `radius`, `color`, `coreColor`, and `progress`, a 0..1 looping clock from `usePortalProgress`) plus a plain `variant` (`'vortex'`, `'rift'`, `'warp'`) and `mirrored`. Every part is drawn round (0, 0) inside a Group translated to the center, so the parts that spin are nested Groups with a derived `rotate`, and `mirrored` is a `scaleX: -1` Group between the two. Spins and pulses are whole turns per loop (`portalSpin`, `portalPulse` in `portalGeometry.ts`, all worklets), so the clock's wrap from 1 to 0 never jumps. Stroke widths scale with the radius but have px floors (`portalStroke`), since a Snake gate is about 7px across. Nothing is drawn outside `radius`. DuelTastic's gates use the vortex, mirrored for the second pair; Jay saw all three looks (2026-11-08) and picked the vortex for the gates, and the other two stay as variants. The Skia mock's PathBuilder gained `moveTo`/`lineTo` (shared, chainable, like `addArc`).
